# Frontend & Extension Integration Quickstart

This document highlights the critical integration points for the React Web Dashboard (**Bhumika**) and the VS Code Extension (**Divyanshi**). 

For your full feature requirements, refer to your official PDF Role Docs. For the exhaustive JSON schema, refer to `API_CONTRACT.md`.

---

## 🔑 Critical JSON Mappings
When fetching the completed scan JSON from Bhavya's API, these are the exact keys generated by the LangGraph AI Engine that you must map to your UIs:

1. `wargame_status`: Determines the UI state. Values are `"Neutralized"`, `"Exploit Confirmed"`, or `"PoC Failed"`.
2. `ai_reasoning`: The markdown explanation of the vulnerability.
   * **Bhumika:** Render this in your "Contextual AI Chat Assistant" panel.
   * **Divyanshi:** Render this in your VS Code Hover tooltip.
3. `poc_script`: The exact Python/Bash exploit script used by the Red Agent.
4. `patch_code`: The generated fix.
   * **Bhumika:** Pass this string into your "One-Click Pull Request" GitHub API integration.
   * **Divyanshi:** Pass this string into your `CodeActionProvider` to inject the patch into the developer's local file.

---

## 🚫 Critical Blockers & Rules

*   **Bhumika & Divyanshi (Blocked by Backend):** You cannot wait for Bhavya to finish the actual database. You must immediately request a "Mock API Endpoint" from her that returns a static version of `API_CONTRACT.md` so you can start building your components today.
*   **Divyanshi (.gitignore Rule):** When building the "Zip & Ship" logic, you **MUST** respect `.gitignore` files. If your VS Code extension zips a user's `node_modules` folder and uploads a 500MB payload, the AI Engine will crash.
*   **Divyanshi (Path Integrity):** The zipped workspace must preserve relative file paths (e.g., `src/database/queries.py`). Do not flatten the zip file, or the AI Engine will fail to locate the vulnerable files.
