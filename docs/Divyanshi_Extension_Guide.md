## 1. Authentication (Supabase)

The extension **must** handle real user authentication via Supabase so that scans are properly linked to the user's account in the database.


### Requirements:
*   **Install SDK:** You must use the official Supabase JS client (`@supabase/supabase-js`).
*   **TypeScript Config:** Because this is a Node environment, add `"DOM"` to the `"lib"` array in your `tsconfig.json` so the Supabase SDK types compile correctly.
*   **Credentials:** Use the Supabase Project URL and the **Anon Public Key** (NOT the Service Role key).
*   **Session Management:**
    *   Initialize the client with `persistSession: false`.
    *   Store the user's `refresh_token` securely using VS Code's `vscode.SecretStorage`.
    *   On extension startup (in `activate()`), automatically retrieve the refresh token from `SecretStorage` and call `supabase.auth.refreshSession()` to keep the user logged in across VS Code restarts.
*   **Commands:**
    *   `aurix.login` (or similar) to handle Login & Sign Up.
    *   `aurix.logout` to clear the `SecretStorage` and sign out of Supabase.
*   **API Requests:** Every request to the Render backend must include the header: `Authorization: Bearer <user_jwt_token>`. Before sending a request, ensure the token isn't expired; if it's close to expiring, refresh it first.

## 2. Dispatching a Scan Job

When the user clicks "Scan Workspace", the extension must package the code and send it to the backend.

### The Pipeline:
1.  **Auth Check:** Before zipping anything, check if the user is logged in. If not, prompt them to log in first.
2.  **Zip the Workspace:** 
    *   Use a library like `archiver` to create a `.zip` of the user's current workspace directory.
    *   **Crucial:** Exclude heavy/irrelevant folders (`node_modules`, `.git`, `venv`, `out`, `dist`) to keep the payload small and fast.
3.  **Upload to Render Backend:**
    *   **Endpoint:** `POST https://major-project-yo0n.onrender.com/api/scans/upload`
    *   **Headers:** `Authorization: Bearer <user_jwt_token>`
    *   **Body:** `multipart/form-data` containing the zip file.
4.  **Response:** The backend will upload the zip to Supabase Storage, push the job to the AWS queue, and return a `scan_id` (e.g., `{ "scan_id": "f069f1e2..." }`).

## 3. Polling for AI Engine Results

The AI Engine running on AWS takes a few minutes to process the code (running SAST tools, triage, and Red/Blue LangGraph agents). The extension needs to poll the backend to get live status updates and the final report.

### The Polling Loop:
*   **Endpoint:** `GET https://major-project-yo0n.onrender.com/api/scans/:scan_id`
*   **Headers:** `Authorization: Bearer <user_jwt_token>`
*   **Interval:** Poll every 5 seconds.
*   **Status Handling:**
    *   If `status === 'PENDING'`, the job is queued.
    *   If `status === 'SCANNING'`, the static analysis tools are running.
    *   If `status === 'ANALYZING'`, the AI agents (Red/Blue/Triage) are active.
    *   If `status === 'COMPLETED'`, the scan is done. Stop polling and read the `findings` array.
    *   If `status === 'FAILED'`, stop polling and show an error message.

## 4. Rendering the Report & Applying Patches

Once the scan is `COMPLETED`, the API will return an array of `findings`.

### Finding JSON Structure (Important Fields):
*   `title`: The name of the vulnerability (e.g., "dangerous-system-call"). *(Note: Use `title`, not `vulnerability_type`)*.
*   `description`: AI-generated explanation of the issue.
*   `file_path`: The relative path to the vulnerable file (e.g., `app.py`).
*   `line_number`: The line where the vulnerability was found.
*   `patch_code`: The safe code snippet generated by the Blue Agent. *(Note: We are updating the backend to ensure this always contains the final safe code block, fallback to `suggested_fix` if empty).*

### UI/UX Requirements:
*   **Path Resolution:** The `file_path` returned by the backend is relative (e.g., `app.py`). To open the file or apply a patch, your extension must prepend the absolute path of the user's current workspace: `path.join(vscode.workspace.workspaceFolders[0].uri.fsPath, finding.file_path)`.
*   **Diff Preview:** Provide a button to open VS Code's side-by-side Diff Editor showing the original file vs. the `patch_code` applied in memory.
*   **State Management:** Ensure your UI variables (like `scanInProgress` flags) are properly reset in a `finally` block if the scan completes or errors out, so the user isn't permanently locked out of scanning again.

### Summary Checklist for End-to-End Testing:
- [ ] User can sign up for a new account via the extension.
- [ ] User can log out and log back in.
- [ ] VS Code restart keeps the user logged in.

- [ ] Polling UI shows real-time status updates (Scanning -> Analyzing -> Completed).
- [ ] Vulnerability UI renders the correct `title`.
- [ ] "Apply Patches" correctly resolves the local file path and modifies the user's code.
